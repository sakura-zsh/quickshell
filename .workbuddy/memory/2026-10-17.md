## 共享壁纸（所有工作区一张壁纸，总览不再出现黑底）

需求（sakura）：现在的壁纸是"每个工作区一张"，`Mod+O` 进 niri 总览后每个工作区各带一份壁纸、间隙是黑的；他在 noctalia 下习惯的是"只有一张壁纸，动的只有窗口"。要后者。

**最终解法（已生效，sakura 确认"就是这个效果"）：纯 niri 配置，QML 一行没动。**
`~/.config/niri/cfg/backdrop.kdl` 加两条 `place-within-backdrop`（`^caelestia-background$` + `^quickshell:Backdrop$`），配合 `layout.kdl` 里已有的 `background-color "transparent"`。详见 MEMORY.md。

过程中走的弯路（教训，已回滚）：先写了 `modules/background/SharedWallpaper.qml` + 插件 `workspaceViewOffsets` + 设置里两个开关，按"每个工作区一列壁纸"去跟随总览 → 实测**背景全黑**（`CUtils` / `Niri.workspacePositions` 任一取值失败就会让所有列"停泊"到屏幕外，只剩 `Background.qml` 那个黑底），白折腾一轮。**遇到"layer surface 在总览里跟着工作区跑"这类问题应先查 niri 的 overview 文档**，官方早就有 layer-rule。

## 任务栏功能区化：模块自带的胶囊必须让位

sakura 报「有些功能区没有背景，变成纯色的了」+ 更早的「多了一些无意义的白色块」，都是同一个根因的两个方向：

- 只在 `Bar.qml` 加 `zoneBg` 但不管模块 → 模块自己的胶囊在岛内，露出亮边 = 白色块。
- 干脆删掉 `zoneBg` → logo / 时钟 / power 这些本来没有胶囊的模块就"裸"在壁纸上。

正解：`zoneBg` 保留，zones 打开时让 Tray / StatusIcons / ActiveWindow / Workspaces 的颜色变透明（`Config.border.enabled &&` 串进颜色绑定），统一由 `zoneBg` 出底；pinned 的时钟槽位不画 `zoneBg`（宽度为 0，会变成 20px 白条），灵动岛自己带黑底。

验证：`.workbuddy/verify` 里 `gen_harness.py` + `t7/t8` —— 关边框后逐条目打印胶囊矩形，间距 12px、时钟不画、logo/workspaces/activeWindow/tray/statusIcons/power 各有块；开边框时与原版 `IDENTICAL = true`。**harness 的 `Config.bar.entries` 必须跟真实 shell.json 的顺序一致**，否则 `isCentredModule` 判错，测试会给出相反的结论（这次就被旧顺序坑了一次）。

以上 QML 改动已随 commit `3270a56` 推到 `origin/main`（sakura-zsh/quickshell）。



关键事实（已核实，niri 26.04）：

- workspace 内容（含 Background 层里"归属该工作区"的 layer surface）会被合成器跟着工作区一起平移缩放：总览里 niri 会把它内缩成一圈"边框"、窗口叠在它上面。所以**只要 surface 还在 background 层且属于某工作区，就一定会动**，纯 QML 无法让它静止。
- 只有 `--json outputs` / `layout` 里有 2D 布局；workspace 层面没有任何位置字段。
- 事件流里有 `Overview opened or closed`；请求 `"OverviewState"` 返回 `{"Ok":{"OverviewState":{"is_open":bool}}}`；`"WorkspacePositions"` 请求**不存在**（`error parsing request`）。若将来 niri 加了 `WorkspacePositionsChanged`，插件已会解 `positions[].{output,workspace_id,view_offset.x}`。

改动：

- `config/BackgroundConfig.qml`：新增 `sharedWallpaper: true`、`sharedWallpaperPad: 20`；`Config.serializeBackground()` 同步。
