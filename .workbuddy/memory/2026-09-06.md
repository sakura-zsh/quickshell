## ⚠️ quickshell 热重载新增 service 文件的坑（重要）

运行中的 quickshell 实例热重载时**新增** `qs.services` 成员文件会以降级上下文编译：
1. `Component.onCompleted`（Component 附加对象）无法解析 → 报 "Non-existent attached object"；
2. 缺少 `import Quickshell` 时根类型 `Singleton` 解析失败 → 报 "Singleton is not a type"（即使 import 了 QtQuick / Quickshell.Io / Caelestia）。
两个限制在 shell **重启后**的冷加载中不存在（Niri.qml 等老文件同样写法运行正常）。排查手段：改 shell.qml 内容触发 reload → `quickshell log -t N` 看错误链。系统 `/usr/bin/qmllint` 是 Qt5 旧版不可用，用 `/usr/lib/qt6/bin/qmllint`（仅语法检查，qs.* 模块解析告警可忽略）。

## 单信号源自动恢复

- 需求：用外接屏时用户会关闭内屏；拔掉外接屏后，niri 不会自动把唯一剩下的内屏重新打开，导致没有可用输出。
- 实现：`DisplayService.qml` 监听 `NiriIpc.outputsChanged` / `availableChanged`，并在加载后延迟检查一次；当 `outputList.length === 1` 且该输出没有 `logical`（即处于 off/disabled）时，静默执行 `niri msg output <name> on`，复用现有串行命令队列，不做 toast 避免吵。
- 加了 `_autoOnName` / `_autoOnQueued` 去重，避免输出事件抖动时重复入队。
- 由于 `DisplayService` 原本只在打开显示器设置面板时才被实例化，无法在冷启动/未打开过面板时兜底；在 `shell.qml` 中用 `property var _displayService: DisplayService` 让它随 shell 常驻。

## 缩放切换导致 quickshell 崩溃修复

- 现象：在“显示器”设置页里切换缩放（125%/滑块等）会让 quickshell 中止并自动重启；崩溃栈指向 `QtWaylandClient::QWaylandWindow::setScale` → `QQuickWindow::physicalDpiChanged`。
- 复现/确认：手动执行 `niri msg output ... scale` 时，如果设置浮动窗口没有打开不会崩；打开控制中心后执行同样命令就会崩。所以是“设置窗口开着时改变输出 scale”触发 Qt/Quickshell Wayland 崩溃。
- 修复：`DisplayPane.qml` 新增 `applyScale()`，先调用 `root.session.root.close()` 关闭设置浮动窗口，再调用 `DisplayService.setScale()`。预设缩放按钮和自定义滑块松手都改走 `applyScale()`；如果选中的就是当前缩放则直接跳过不关窗。
- 注意：其它显示器操作（mode/transform/position/vrr）不需要关窗，只有 scale 会影响 Wayland output DPI/scale 事件。

## 缩放后设置页仍显示 100% 修复

- 原因：`niri msg output ... scale` 后 niri 不会发 `OutputsChanged` 事件（实测 event-stream 只有 Window layouts changed），所以 `NiriIpc.outputs` 缓存一直是旧值，重开设置页仍显示旧缩放。
- 修复：`DisplayService.qml` 把 `outputs` 改为本地可变镜像；新增独立 `refreshProc` 执行 `niri msg --json outputs`，在所有输出配置命令成功后主动解析并更新 `outputs`。为避免频繁刷新互相覆盖，带 `_refreshRunning` / `_refreshQueued` 合并。
- 另外把 `DisplayPane.qml` 的 `selectedObj/selectedEnabled/selectedLogical/selectedMode` 改为直接绑定 `DisplayService.outputs`，并让 `selectedMode` 显式依赖 `selectedObj`，保证刷新后 UI 能自动更新（仅靠调用函数不会建立依赖）。
