
## bar 布局重排：窗口标题移到左侧、时钟移到中间（09-23）

- 需求：activeWindow 从中间挪到 workspaces 右侧；clock 从右侧挪到中间。
- 实现：只改 shell.json 的 bar.entries 顺序 —— logo, workspaces, activeWindow, spacer, clock, spacer, tray, divider, statusIcons, divider, power, idleInhibitor。
- 配套代码改动：新增 Config.bar.activeWindow.maxWidth（默认 0 = 原行为），用户配置设为 360。原因：ActiveWindow.maxWidth 原本 = bar.width - 其他模块宽度 - 间距 - 内边距，且计算时把 spacer 排除在"其他模块"之外，等于可吃光 spacer 的空间；标题长时会挤掉 spacer，把居中的 clock 顶偏。
- 分隔线变化：原 [tray] | [clock statusIcons] | [power] 变为 [tray] | [statusIcons] | [power]（clock 移出该组到中央）。

## bar 居中补偿修复 + 药丸高度对齐（09-23 第三轮）

- 修法：只用 spacer 索引做区间运算（求和区间 [0, idx0) 与 [idx1+1, count) 由索引推出，spacer 结构上无法进入求和），另加 width*0.25 安全钳制。

## 时钟位置手动旋钮（09-23 第四轮）

- 用户要求自己调时钟位置。新增 Config.bar.clock.offset（int, px, 正数右移/负数左移），默认 0，已写入用户 shell.json 的 bar.clock.offset。
- 实现：Bar.qml spacerPreferredWidth 中 manual = off>0 ? 加到左 spacer(2*off) : 加到右 spacer(-2*off)；auto 与 manual 各自独立钳制在条宽 25% 以内，保证手动偏移始终有满量程（±320px @2560）。
- 换算关系：offset 值 = 时钟需要移动的像素数（1:1 生效，因为两端各挪一半）。
- 用户自行调整方式：改 shell.json 数字即可，Config 热重载。

- 现状：仓库 1568 个文件属主 root；~/.config 限深 3 共 3879 个条目属主 root；niri_caelestia/shell.json 也是 root。

## 时钟位置钉死（09-23 第七轮）

- 用户自查发现：时钟位置不是固定的，随左侧工作区/标题、右侧 status 宽度变化而漂移 —— 与我的判断一致（它被放在两个等分 spacer 之间的"空闲区中心"）。
- 前两次"数学补偿"均不成立（第一次自反馈放大，第二次量算被邻居变化影响），故改为结构性方案：
  * 时钟槽位 Layout.preferredWidth = 0（不占宽度）
  * 时钟放入包装 Item 内，x = root.width/2 + Config.bar.clock.offset - slot.x - width/2

  * pinned 判定：root.isCentredModule(index)（该条目位于两个 spacer 之间时才钉住，否则按原流式布局）。
- 关键坑：Loader 会把"直接子项"尺寸改成自己的尺寸，所以 Layout.preferredWidth=0 的 Loader 会把时钟压成 0 宽 → 必须在 Loader 与时钟之间包一层 Item。

- 已固化为 skill：~/.workbuddy/skills/qml-layout-headless-verify/（SKILL.md + scripts/verify_geometry.py + scripts/probe.qml，脚本已冒烟通过）。

## dock 微信图标异常（09-23 第八轮）

- 现象：dock 里微信图标显示为占位/异常。
- 排查链：
  1. 图标文件本身正常：hicolor 7 个尺寸 PNG（512/256/128/64/48/32/16）都是规范 PNG；Papirus 的 wechat.svg 渲染出来是正常的绿+白气泡（用 PySide6 QtSvg 渲染后目视确认）。
  2. 活动图标主题 = Papirus-Light（gsettings），Papirus-Light/48x48/apps/wechat.svg 存在。
  3. 真正断点在**配置的 pinned id**：用户 dock 里微信条为 id="com.qq.weixin"（Deepin 版包的 id），而本机装的是 portable 包 → desktop 条目是 /usr/share/applications/com.tencent.wechat.desktop。8 个 pinned 条目里只有它没有对应 desktop 文件。
  4. DockItem.qml 图标表达式为 `entry?.icon || root.desktopId() || root.app?.icon`：entry 解析失败（null）→ 取 desktopId()="com.qq.weixin" → 而该名字任何主题都没有 → Quickshell.iconPath 落到 "image-missing" 占位图。
- 验证：PySide6 里显式设 QIcon.setThemeSearchPaths([~/.local/share/icons,/usr/share/icons]) 后对比 —— com.qq.weixin 在两个主题都 found=False；wechat 都 found=True。（注意：沙箱内 themeSearchPaths() 默认是空的，必须显式设。）
- 顺带排除的错误猜想：Quickshell heuristicLookup **只做 id 精确匹配 + StartupWMClass 精确匹配，不匹配 Exec**（读 rev 916a0dd9 源码确认），所以 exec="env" 不是图标问题的原因。
- 修法：
  * 代码：modules/dock/DockItem.qml 图标优先级改为 `root.app?.icon || entry?.icon || root.desktopId()` —— 显式配置的图标优先，陈旧 id 不再能把查找带偏。
  * 配置：pinned 条目修正为 id="com.tencent.wechat"、exec="/usr/bin/portable"、match=["com.tencent.wechat","wechat"]。
- 遗留发现（未改，待用户决定）：dock 的 launchApp() 回退分支是 `Quickshell.execDetached([exec])`，**单个 token**，所以任何多词的 exec 都会静默失败；原配置的 exec="env" 就是点了没反应（现在 entry 能解析，走 Apps.launch(entry) 正常）。
