3. Dock 图标紫/黑方块（2026-07-23 已修复）

根因：

- Quickshell DesktopEntries 的 id **不带** `.desktop` 后缀
  （例如 `obsidian`、`code`、`ChatGPT`，不是 `obsidian.desktop`）
- Dock 原先写的是 `id: "obsidian.desktop"` 等
- `Icons.getAppIcon("obsidian.desktop")` → heuristicLookup 失败
  → 返回空图标 URL：`image://icon/?fallback=obsidian.desktop`
  → 显示为紫色/黑色方块

修复：

1. modules/dock/Dock.qml
   - id 去掉 `.desktop`
   - 增加显式 icon 字段（如 code→vscode、ChatGPT→chatgpt-desktop）
   - ChatGPT exec 改为 `chatgpt-desktop`

2. modules/dock/DockItem.qml
   - 不再用 CachingIconImage（更适合文件/照片缓存）
   - 改用 IconImage + Quickshell.iconPath（与 launcher/workspace 一致）
   - resolveEntry / resolveIcon：byId → heuristicLookup → 显式 icon

3. utils/Icons.qml getAppIcon
   - 自动 strip `.desktop`
   - 优先 byId，再 heuristicLookup
   - 查找失败时不再生成空的 `image://icon/?fallback=...`

验证（offscreen quickshell）：

obsidian → image://icon/obsidian?fallback=image-missing (hasTheme=true)
code → image://icon/vscode?fallback=image-missing
ChatGPT → image://icon/chatgpt-desktop?fallback=image-missing
连旧的 obsidian.desktop 也能正确解析到 obsidian 图标


3b. FlClash 无法启动/无运行圆点（2026-07-23 已修复）

根因：

- desktop 文件 StartupWMClass=com.follow.clash
- niri 窗口 app_id 实际是 com.follow.clash
- Dock 原先 match 只有 flclash / FlClash
- 结果：isRunning=false（无小圆点）；点击以为“未运行”去二次启动，
  单实例应用不聚焦旧窗口，看起来像点了没反应

修复：

- Dock.qml flclash.match 增加 com.follow.clash
- DockItem 自动把 DesktopEntry.startupClass 加入匹配候选

十一、图标方案（正确做法）

DesktopEntries.byId("obsidian")
DesktopEntries.heuristicLookup("code")  // icon 字段是 vscode

Quickshell.iconPath(entry.icon, "image-missing")

IconImage { source: ...; implicitSize: 48 }

十六、桌面歌词（2026-07-23 已实现）

modules/lyrics/
  Wrapper.qml        - 底部 overlay 窗口（在 Dock exclusiveZone 上方）
  DesktopLyrics.qml  - 毛玻璃 pill：上一句 / 当前句 / 下一句 + 曲名

services/Lyrics.qml
  - 绑定 Players.active（MPRIS，Cider 等）
  - LRCLIB 拉取逐字时间轴歌词（synced LRC）或纯文本
  - 内存缓存按 trackKey
  - 播放中 250ms 刷新 position 对齐当前行

配置：
  Config.services.desktopLyrics = true  // ServiceConfig.qml

交互：
  左键：播放/暂停
  中键：下一曲

数据流：
  MPRIS metadata → LRCLIB API → parse LRC → 当前行高亮
